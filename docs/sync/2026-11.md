## Scope

The candidate is the last commit before `ee43be113e` (2026-09-28), which
enables the ACP v2 types and begins the migration that reaches SDK 3.4 by
2026-10-17. This round stops at that boundary. The v2 schema is unstable
upstream, the actus contract is telos's own WebSocket protocol, and the
migration replaces the shared content, tool, session, and permission types
across `acp_thread`, `agent`, and `agent_servers`. Taking it in the same
round would mix a protocol rewrite with the behavior fixes this window
carries. The next round starts at the boundary.

Within that boundary the port keeps the agent path only. Editor, language
editor, LSP view, git commit view, remote transport, theme, and benchmark
changes were reverted even where they were in the candidate window. The
retained set is the agent loop, the ACP thread and servers, the language
model layer, the fs watcher, the terminal raw-output path, and the settings
the agent reads.

## Port shape

- `acp_thread` takes upstream's restructured `MessageContent`, `ContentBlock`,
  and `RenderBlock` with retained source blocks, and keeps telos's
  `MessageText` as the text entity. Message text has no renderer in this cut,
  so the markdown-only helpers are gone.
- The streaming reveal uses upstream's source cursor. Telos keeps its
  `EntryUpdated` emission: the reveal announces the bytes it commits, which
  `test_streaming_reveal_announces_the_text_it_commits` pins.
- `crates/terminal` takes the raw-output split so a PTY byte stream keeps its
  control sequences. The settings-only path-hyperlink work is not ported.
- The retained providers drop the `ui`-backed settings views. The
  non-compatible providers return `ProviderSettingsView::ApiKey` data, the
  compatible providers return `None`, and both keep their `icons` icon. The
  provider behavior, model metadata, and request conversion come from the
  candidate.
- `crates/telos/src/stub_backend.rs` follows the new shape: the provider
  returns a plain `LanguageModel` and implements `LanguageModelClient`.
- The port removes `portable-pty` from `acp_thread` and `take-until` from
  `util`. The lock drops both and their transitive crates.
- The language model dependency set is trimmed to what the retained providers
  use. `language_models_cloud`, `cloud_api_client`, `cloud_api_types`, `sha2`,
  `base64`, `fs`, and `rand` leave `language_models`, and the
  `language_models_cloud` crate is removed from the workspace. The no-caller
  `anthropic/telemetry.rs` module and the `zed.dev` provider ordering in the
  registry are removed.

## Known gaps

- The ACP v2 migration is not measured against a live ACP agent server. The
  `acp_thread` and `agent_servers` suites cover the v1 path.
- The actus repository no longer carries `run.sh --scenarios-stub`. The
  structural gate is `./run.sh --test` with the telos binary as
  `ACTUS_EXECUTOR_BIN`. The live chat round trip in that suite is opt-in and
  targets actus's external CLI stub, so it does not exercise telos's
  `TELOS_STUB_BACKEND`.
- The `acp_thread` idle-sleep tests remain out. The gpui test-support
  accounting they need is not in the cut. The suite runs 143 tests.
- `crates/gpui` and the platform crates remain unported, as in the 2026-09
  round.
- The workspace still carries four out-of-graph members: `extension_host`,
  `language_extension`, `theme_extension`, and the telos-owned
  `telos_settings`. The first three are dev or optional-feature paths, and
  `telos_settings` is the format the launcher writes. None is in the telos
  binary. `grammars` left this list when the language layer linked its
  configs and queries.
- `create_thread` and `list_agents_and_models` have no sibling-thread host in
  telos. If their feature flag is enabled, the tools fail with a clear error.
  Wiring a host or removing the tools is a separate decision.
- The optional `unit-eval` module and its 1.2 MB fixture set were removed.
  The feature was not part of any gate.
