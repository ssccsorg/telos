Defect found and fixed. `crates/agent_servers/src/acp.rs` polls the ACP
connection future on `background_spawn` after the port, where telos had it on
`spawn_dedicated`. Upstream made that move when the ACP SDK began bounding its
dispatch-chain stack usage. The site is category (b), telos had not diverged
there, so the copy took upstream's version and the protection went with it. The
protection is not about upstream's runtime: `crates/gpui/src/executor.rs`
documents that background tasks run on whatever threads the platform dispatcher
provides, and on macOS those are GCD workers whose stacks the kernel fixes at
512 KiB. In unoptimized builds the ACP dispatch chain needs about 0.5 MiB per
inbound message, so dropping the dedicated thread is a crash waiting for the
first message a dev build receives. Restored, with the reason recorded in the
code and in `VENDORING.md`.

Lesson: a category (b) copy can drop a protection that telos's *cut* depends on
even when telos never diverged at that line. The upstream change is safe for
upstream's runtime, and the cut's runtime differs. Category (b) deserves a read,
not just a copy.

### Startup panic from a stale embedded default settings

The first stub run failed with `Option::unwrap()` on `None` in
`agent_settings.rs`. The cause was outside `crates/`: `assets/settings/default.json`
carries the defaults for `threads_sidebar` and `prevent_idle_sleep`, upstream
changed it in this window, and the file was never in scope because the port set
was derived from `crates/` only. The `settings` crate embeds that file at build
time through `fs_embed!`, so a stale copy panics at startup and no compile step
catches it. Add `assets/` to the port set, and rebuild the release binary after
touching an embedded asset.

### Known gaps after the port

- `cargo check --workspace --all-targets` fails in `acp_thread`'s tests. Upstream threads `IdleSleepPrevention` through the thread and tests it against gpui test-support accessors (`active_idle_sleep_preventions`, `set_idle_sleep_prevention_delay`, `set_idle_sleep_prevention_fails`). The gpui cut has the no-op `ActivityGuard` but not that test-support accounting. Test targets are outside the documented gates, and the behavior suites of zed-derived crates live upstream. Twenty-six files were removed again. Test membership against the `members`

## The one repeated divergence

`crates/acp_thread/src/acp_thread.rs` defines `MessageText` as the replacement
for the removed `markdown::Markdown` component. Every conflict in the merge of
that file is this single substitution, in one of these shapes:

- `ContextCompaction`, where upstream restructured `summary` to `Vec<ContentBlock>` and added `error`
- `ToolCall.label`, where upstream added `title`, `new_label`, and `label_text`
- `ContentBlock`, where upstream added `Image` and `Unsupported` and removed `append`
- `AcpThread::invalidate_mermaid_caches` and `ContentBlock::markdowns()`, which have no telos counterpart

## Resolution policy

Telos's unilateral decisions stand, and upstream's behavior is taken where it
does not depend on them. Applied per site:

- Adopt upstream's structure and substitute `MessageText` for `Entity<Markdown>`.
- Drop code that exists only for markdown rendering or mermaid.
- Keep telos's own additions: the `MessageText` type, the telos block after `pub use mention::*;`, the telos test block, and `agent_servers/src/connection_cache.rs`.
- Keep telos's cut boundaries when upstream lands inside them.

## Cut-boundary items found in the first pass

Each of these is an upstream change that lands inside a subsystem telos cut, and
each needs one decision recorded:

- `markdown`. Upstream's `acp_thread` dev-depends on the crate and its content model keeps `Entity<Markdown>`. telos removed the crate. Resolution: remove the dependency line, keep `MessageText`.
- `ActivityGuard`. Upstream added it to gpui in `450775244f` and `acp_thread` now imports it and stores it in a connection state variant. telos's gpui cut does not define it, and upstream's implementation spans the macOS and Linux platform layers. Decision needed: add a headless no-op to the cut, or drop the import and the state field.
- `rust-embed`. Upstream removed the direct dependency from `agent`, while telos's `agent/src/templates.rs` still uses `rust_embed::RustEmbed`. The merge drops a line telos needs. Resolution: keep telos's `rust-embed.workspace = true`.
- `agent_settings`. Upstream's `acp_thread` uses it and telos already carries it. No conflict.
- `mermaid`. Upstream added `invalidate_mermaid_caches` and `markdowns()`. Resolution: ignore both.
- `ContentBlock::append`. Upstream removed it and moved to rebuilding blocks. Any remaining telos caller has to move to the rebuild path.
