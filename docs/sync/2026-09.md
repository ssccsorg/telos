Status: port in progress on branch `13-zed-upstream-sync`, working tree dirty.

## Third pass: the blanket port and the final blocker

Deriving the port set from the telos drift list failed repeatedly, so this pass
derives it from `git diff --name-only <pin>..<candidate>` over `crates/` and
tests membership by reading the root manifest for a `crates/<name>` reference.
The member list built from the `members = [...]` block was incomplete: it missed
`extension_host`, `grammars`, `language_extension`, and `theme_extension`, each
of which the trait changes in `lsp` and `language` had made stale.

Result after this pass: the workspace compiles except `language_models`.

Decisions applied:

- `buffer_diff` adopts upstream's `DiffOperations`. `acp_thread/diff.rs` is a category-(b) file that the first pass skipped because the whole crate was excluded from the blanket pass, so its upstream API migration never landed.
- The gpui cut gains a no-op `ActivityGuard` and `App::prevent_idle_sleep`, which keeps ported agent code close to upstream. A headless server has no desktop to keep awake.
- `util` gains `fs_embed`, the root `rust-embed` declaration gains the `compression` feature, and `arc-swap` joins the workspace dependencies.
- `agent_settings` and `settings_content` are category-(b) crates the first list missed. `settings_content` is identical to the pin, so its eight changed files are pure copies.
- `assets` adopts `util::fs_embed!` with the same asset set it already had, so nothing about the headless asset surface changes.
- Cut-boundary keeps: `terminal` drops upstream's mouse handling, `icons` drops upstream's new `IconName` variants, and the markdown/mermaid surface stays out.

Final blocker, and it is exactly the constraint this round was given. The four
retained provider files in `language_models` (`anthropic.rs`, `deepseek.rs`,
`open_ai.rs`, `open_ai_compatible.rs`) each `use ui` in their upstream form, for
the provider settings view. telos keeps the providers and cut the `ui` crate, so
the remaining work is to take the provider behavior (streaming, event mapping,
prompt cache keys, token counting, the new model variants `open_ai::Model::SixAstra`
and `deepseek::Model::V4Flash`) and drop the settings-view code. `OpenAiEventMapper`
also moved out of `provider::open_ai` and needs re-pointing.

Everything below `language_models` now compiles, including `acp_thread`,
`agent_servers`, `agent`, `extension_host`, `grammars`, `language_extension`,
`theme_extension`, `language_models_cloud`, and `buffer_diff`. The gates after
the model layer are untested.

## Second pass: systematic file port

The (b) category is the bulk of the work, and driving it crate by crate from the
compiler is a cascade. Raising `settings_content` pulled in `settings`, which
pulled in `util`. Raising `fs_watcher.rs` pulled in a new module directory. Port
the whole upstream changed-file list over the kept crates in one pass instead.

Applied in this pass:

- `crates/agent`, `acp_thread`, `agent_servers`, `language_model`: merged and the drifted-file conflicts resolved.
- 89 upstream-changed files over `settings`, `theme`, `theme_settings`, `syntax_theme`, `project`, `language`, `language_core`, `lsp`, `fs`, `git`, `text`, `streaming_diff`, `html_to_markdown`: 51 copied, 19 merged where telos had drifted, 19 skipped.
- New upstream files created: `language_model_core/src/chat_completion.rs`, `language_core/src/highlight_cache.rs`, `fs/src/git_clone_progress.rs`, `fs/src/fs_watcher/diagnostics.rs`, `project/src/lsp_store/emmet_ext.rs`.
- `settings_content` and `agent_settings` are identical to the pin, so their upstream changes are pure copies. `acp_tools` is not a telos crate and its upstream change is ignored.
- `language_models` stays at the telos baseline. Only the retained providers (`anthropic`, `deepseek`, `open_ai`) carry their upstream changes, and a later pass has to finish that selection.
- Cut-boundary work: the gpui cut gains a no-op `ActivityGuard` and `App::prevent_idle_sleep`, `acp_thread` loses `invalidate_mermaid_caches` with the mermaid strip, the `markdown` dev-dependency is removed, and `agent`'s `rust-embed` line is kept.

Where it stopped, with the manifest valid and no conflict markers outside the
prompt template:

- `crates/util` is the next blocker. Upstream replaced the settings asset mechanism with `util::fs_embed`, and the ported `settings` now references it. `util` was not in the ported path list.
- `external_websocket_sync` still needs its hand adaptation.
- `agent` and `agent_servers` are unverified because the dependency chain stops earlier.
- The retained-provider selection for `language_models` is unfinished.
- The gates have not been run.

Lesson: derive the port set from `git diff --name-only <pin>..<candidate>` over
every kept crate. The telos drift list and a hand-picked path list both miss
crates that upstream touched and telos consumes, which is how `agent_settings`,
`settings_content`, `settings`, and `util` were each found late.

## The one repeated divergence

`crates/acp_thread/src/acp_thread.rs` defines `MessageText` as the replacement
for the removed `markdown::Markdown` component. Every conflict in the merge of
that file is this single substitution, in one of these shapes:

- `ContextCompaction`, where upstream restructured `summary` to `Vec<ContentBlock>` and added `error`
- `ToolCall.label`, where upstream added `title`, `new_label`, and `label_text`
- `ContentBlock`, where upstream added `Image` and `Unsupported` and removed `append`
- `AcpThread::invalidate_mermaid_caches` and `ContentBlock::markdowns()`, which have no telos counterpart

## Resolution policy

Telos's unilateral decisions stand, and upstream's behavior is taken where it
does not depend on them. Applied per site:

- Adopt upstream's structure and substitute `MessageText` for `Entity<Markdown>`.
- Drop code that exists only for markdown rendering or mermaid.
- Keep telos's own additions: the `MessageText` type, the telos block after `pub use mention::*;`, the telos test block, and `agent_servers/src/connection_cache.rs`.
- Keep telos's cut boundaries when upstream lands inside them.

## Cut-boundary items found in the first pass

Each of these is an upstream change that lands inside a subsystem telos cut, and
each needs one decision recorded:

- `markdown`. Upstream's `acp_thread` dev-depends on the crate and its content model keeps `Entity<Markdown>`. telos removed the crate. Resolution: remove the dependency line, keep `MessageText`.
- `ActivityGuard`. Upstream added it to gpui in `450775244f` and `acp_thread` now imports it and stores it in a connection state variant. telos's gpui cut does not define it, and upstream's implementation spans the macOS and Linux platform layers. Decision needed: add a headless no-op to the cut, or drop the import and the state field.
- `rust-embed`. Upstream removed the direct dependency from `agent`, while telos's `agent/src/templates.rs` still uses `rust_embed::RustEmbed`. The merge drops a line telos needs. Resolution: keep telos's `rust-embed.workspace = true`.
- `agent_settings`. Upstream's `acp_thread` uses it and telos already carries it. No conflict.
- `mermaid`. Upstream added `invalidate_mermaid_caches` and `markdowns()`. Resolution: ignore both.
- `ContentBlock::append`. Upstream removed it and moved to rebuilding blocks. Any remaining telos caller has to move to the rebuild path.

## Compiler findings

The pass reached a compiling dependency chain. With the ACP pin raised to
2.2.0, `cargo check -p acp_thread` builds every dependency of `acp_thread`,
including `agent-client-protocol 2.2.0`, `project`, `language_model`,
`context_server`, and `agent_settings`. The remaining 49 errors are all inside
`crates/acp_thread` and fall into eight classes.

| Class | Count | Fix |
|---|---|---|
| `App` not in scope | 35 | add `App` to the gpui import, which telos's set carried and upstream's does not |
| `Markdown` undeclared | 5 | substitute `MessageText` at `acp_thread.rs` 871, 1113, 1115, 3434 and `terminal.rs` 515 |
| `MessageText::new` arity | 4 | telos's constructor takes one argument, so drop the `cx` and markdown-option arguments at 869, 886, 1204, 1603 |
| `gpui::ActivityGuard` unresolved | 1 | the gpui cut does not define it |
| `AgentSettings::prevent_idle_sleep` unknown field | 1 | `agent_settings` carries the idle-sleep setting upstream added, so it belongs in the merge list |
| `Context::prevent_idle_sleep` missing | 1 | same feature |
| `invalidate_mermaid_cache` undefined | 1 | drop `invalidate_mermaid_caches` and `markdowns()` with the mermaid strip |
| `language_registry` not in scope | 1 | `compaction.append_summary` at 3364 references a parameter the enclosing function does not carry |

The idle-sleep pair needs one decision. Upstream threads `IdleSleepPrevention`
through `AcpThread` with about 25 test references. Two shapes are available:
add a no-op `ActivityGuard` and `Context::prevent_idle_sleep` to the gpui cut so
ported code stays upstream-close, or drop the feature and rewrite those tests. A
headless server does not manage desktop idle sleep, so a no-op keeps the cut
honest and the diff small, at the cost of a recorded gpui-surface addition.

`cargo check -p acp_thread` compiles the library only, so the two
`use markdown::parser` sites at 7663 and 7740 did not surface. They sit in tests,
they assert markdown rendering, and they go with the strip.

The deprecation of the merge list is the other lesson: `agent_settings` drifted
in telos and changed upstream in the same window, and the first list did not
name it. The scope has to be derived from the upstream changed-file list, not
from the telos drift list.
