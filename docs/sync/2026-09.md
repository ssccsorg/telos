## The one repeated divergence

`crates/acp_thread/src/acp_thread.rs` defines `MessageText` as the replacement
for the removed `markdown::Markdown` component. Every conflict in the merge of
that file is this single substitution, in one of these shapes:

- `ContextCompaction`, where upstream restructured `summary` to `Vec<ContentBlock>` and added `error`
- `ToolCall.label`, where upstream added `title`, `new_label`, and `label_text`
- `ContentBlock`, where upstream added `Image` and `Unsupported` and removed `append`
- `AcpThread::invalidate_mermaid_caches` and `ContentBlock::markdowns()`, which have no telos counterpart

## Resolution policy

Telos's unilateral decisions stand, and upstream's behavior is taken where it
does not depend on them. Applied per site:

- Adopt upstream's structure and substitute `MessageText` for `Entity<Markdown>`.
- Drop code that exists only for markdown rendering or mermaid.
- Keep telos's own additions: the `MessageText` type, the telos block after `pub use mention::*;`, the telos test block, and `agent_servers/src/connection_cache.rs`.
- Keep telos's cut boundaries when upstream lands inside them.

## Cut-boundary items found in the first pass

Each of these is an upstream change that lands inside a subsystem telos cut, and
each needs one decision recorded:

- `markdown`. Upstream's `acp_thread` dev-depends on the crate and its content model keeps `Entity<Markdown>`. telos removed the crate. Resolution: remove the dependency line, keep `MessageText`.
- `ActivityGuard`. Upstream added it to gpui in `450775244f` and `acp_thread` now imports it and stores it in a connection state variant. telos's gpui cut does not define it, and upstream's implementation spans the macOS and Linux platform layers. Decision needed: add a headless no-op to the cut, or drop the import and the state field.
- `rust-embed`. Upstream removed the direct dependency from `agent`, while telos's `agent/src/templates.rs` still uses `rust_embed::RustEmbed`. The merge drops a line telos needs. Resolution: keep telos's `rust-embed.workspace = true`.
- `agent_settings`. Upstream's `acp_thread` uses it and telos already carries it. No conflict.
- `mermaid`. Upstream added `invalidate_mermaid_caches` and `markdowns()`. Resolution: ignore both.
- `ContentBlock::append`. Upstream removed it and moved to rebuilding blocks. Any remaining telos caller has to move to the rebuild path.
